自分の学習整理ということで。

`enum`は他の言語だと単に値を列挙するための機能で、C/C++だと列挙した値に直接数値を割り当てられたりもするがそのくらいの意味である。  
Rustでも単なる列挙としても使えるが、C/C++とは違った意味で値を割り当てることができるのが特徴だろう。

Rustの2大戻り値系`enum`といえば[`std::option::Option`](https://doc.rust-lang.org/std/option/enum.Option.html)と[`std::result::Result`](https://doc.rust-lang.org/std/result/enum.Result.html)だろう。

## Option

`Option`は、値が有るか無いかという定義である。
値があるという意味の`Some`には値を割り当てることができる。

```rust
pub enum Option<T> {
    None,
    Some(T),
}
```

C/C++だとしばしば「値が0より大きければ意味のある値、0であれば値に変更無し、0未満であればエラー」のような関数の戻り値の定義をすることがある。
そういう定義にしていると、値の範囲が変わって0も意味がある値になったときに途端に困ることになる。
そうなったとき私は`int`のマイナスの最大値を割り当てたりして逃げたりしてたような気がする。

## Result

値が正常かエラーかという定義である。  
これとは別に[`std::error::Error`](https://doc.rust-lang.org/std/error/trait.Error.html)もあるが、こちらはトレイトだ。
`Result::Err(E)`の`E`は`std::error::Error`である必要はないが、そうなっていると便利なことは多いかもしれない。

```rust
pub enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

`Option`の例でも挙げたが、Linuxの定義が先なのかC言語の定義が先なのか、`0`をエラーなしと扱う標準関数がけっこうある。
`if`文などで判定に使うのが「`0`は偽」だし、`bool`の`true`も数値で扱うと非ゼロなのでなんとなく相性が悪いのだが、そういうものだ。

## NoneをErrに

作っている関数の戻り値が`Result`で、その中で呼出した関数の戻り値が`None`だったらすぐにエラーで返して、`Some`だったら処理を続けたいということがある。
そういうときは`.ok_or()`でよい。

```rust
fn hoge() -> Option<u32> {
    None
}

fn main() -> anyhow::Result<()> {
    let v = hoge().ok_or(std::io::Error::new(std::io::ErrorKind::Other, "oh no!"))?;
    println!("{v}");
    Ok(())
}
```

```log
Error: oh no!
```

`.map_err()`はエラーの変換だから違うし、`match`でやるのもちょっと面倒だなあ、というときはそれでよいと思う。
`match`くらい面倒がらずに書けばいいじゃないか、と最初の頃だと思っていたが私も慣れてきたのかもしれない。

なんとなく、手で書くコード量が多いと実質的なのバイナリの量も多くなってしまいそうな気分になるのだろう。
気持ちの問題というかね。

ただ最近ではAIにコードを書いてもらったりレビューしてもらったりすることもあるので、
読む量が少ないようにした方が負荷が少ないという考え方もあるなと思い至った。

例えば、今回使った`.ok_or()`はこういう実装になっている。
うん、そのまんまだ。
自分で同じことをやろうとしたらそういう実装になるだろうから、
それなら最初からあるものを利用したほうがよかろう。
標準にあるから他の人も悩まないだろうし。

```rust
    #[inline]
    #[stable(feature = "rust1", since = "1.0.0")]
    #[rustc_const_unstable(feature = "const_option_ops", issue = "143956")]
    pub const fn ok_or<E: [const] Destruct>(self, err: E) -> Result<T, E> {
        match self {
            Some(v) => Ok(v),
            None => Err(err),
        }
    }
```

こういう箇所に外部のクレートを積極的に利用してまで短くしようという気にはならないのだが、
`anyhow`と`thiserror`は同じ作者だしいいよな(根拠なし)くらいには使っていこうと思う。
