いま、Rustのコードにログを埋め込む作業をしている。めんどくさい。。。

ある程度エラーログは埋め込んでいたのだが、今ひとつだった。

* 埋め込み忘れ
* `match`の`Err(e)`でログ
* `if let Err(e)`でログ
* `.inspect_err(|e|)`でログ

忘れた場合以外はどれもエラーログは吐き出してくれるのだが、統一感がないというのが腹立たしい。
`match`を使うのはそうじゃないと表しづらいとき、
`let Err(e)`を使うのは`anyhow::Result<()>`のとき、
`.inspect_err(|e|)`を使うのは・・・なんだろう？  
自分で明文化したコーディングルールがないし、日をまたいだりちょっと時間が開くと前回どうしたかも覚えてないしで散乱している。

## if let Err と inspect_err のどちらか

`let Err(e)`と`.inspect_err(|e|)`はどちらかに寄せられると思う。  
今のところ`.inspect_err`に寄せる方向で考えている。
`let Err`だと値が取れないので、どちらでも対応できる方にしようかと。

`let Err`が`()`ではない値を返す関数にしか使えないのであれば明示的に見分けがつくという利点もあったのだが、
今は単に値を捨てているだけという可能性もあるので、それなら`.inspect_err`でよいというところだ。  

`let Ok`でエラーは何でも良いというパターンもあるが、
とにかく種類を減らして頭をあまり使いたくないというのが正直なところだ。

## Noneをanyhowエラーにするのにanyhow::Contextを使う

`Option<T>`が`None`だったらエラーにしたいということがある。  
`.ok_or()`や`.ok_or_else()`を使うのが標準的なやりかただが、
`anyhow::Result`でエラーを返していると特定のエラーもないし考えるのが面倒だ。

そういうときに`.context()?`を使うと文字列のエラーにして返してくれる。
`|e|`みたいなもの不要だから固定文字列で良い場合がほとんどだからお手軽で助かる。
どうしてもフォーマットしたいなら`.context_with()?`を使えばよいし。

```rust
use anyhow::{Context, Result};

fn none() -> Option<u32> {
    None
}

fn an_error() -> Result<u32> {
    none().context("Noneですよ")
}

fn main() -> Result<()> {
    let v = an_error()?;
    println!("v={v}");
    Ok(())
}
```

```log
Error: Noneですよ
```

`anyhow::Context::context()`はこんな実装だそうだ。  
`Option<T>`に適用する`Context`トレイトなので`use anyhow::Context`だけあればよいのか。

```rust
impl<T> Context<T, Infallible> for Option<T> {
    fn context<C>(self, context: C) -> Result<T, Error>
    where
        C: Display + Send + Sync + 'static,
    {
        // Not using ok_or_else to save 2 useless frames off the captured
        // backtrace.
        match self {
            Some(ok) => Ok(ok),
            None => Err(Error::construct_from_display(context, backtrace!())),
        }
    }

    ...
```

## tracing::instrument(err)というのもあるらしい

こちらはまだ読んだだけだが、`?`のたびに`.inspect_err`を書くのが面倒であれば`tracing`の`#[instrument(err)]`を関数につけておくと自動でログが出るらしい。
クレートを呼び出してエラーが出た直後ならともかく、そのエラーを上に返していくだけなら`error!("{e}")`で済ませてしまったりするので、それだったらまあいいかと思う。
試していないので、気が向いたらやってみよう。

## matchは深い

`match`を避けているだけのような気がしているが、別にそういうつもりもない。

たとえば、エラーじゃないけど値がない、みたいな状況がある(あった)。  
そうなると`Result<T, E>`だと表しづらいので`Result<Option<T>, E>`にして`Some(None)`があるときれいに書きやすい。

```rust
  match reason_optiont_func() {
    Ok(Some(v)) => ...,
    Ok(None) => ...,
    Err(e) => ...,
  }
```

`match`をなんとなく避けてしまうのは、`if`などで書くより処理本体が1段深くなってしまうからだと思う。
まず`match`があって、次に`Ok(v) =>`のようなアームがあり、最後に処理本体が来る。
大したことを書いているわけでもないのにやたら長い処理を書いているように見えてしまうのだ。

気にしなければよいのだけどね。
