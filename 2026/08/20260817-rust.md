`tracing`でログ出力しているのだが、ログの中にIDを出力させないとどれについてのログなのかわからないのだが、
いちいちIDを埋め込むのが面倒なので最初に設定したらそれが一定の範囲で自動的に出力されてくれないだろうか。

そう思ってspanを使い始めたのだがうまく制御できない。

## instrumentだけではダメ

`instrument`マクロを使うとspanが作られるようだが、spanが有効な範囲でログ出力させないと何も出てこない。  
これは`main()`から`hoge()`を呼び、`hoge()`が`hogege()`を呼んでいるのだが、ログ出力があるのは`main()`だけなのでspanを設定しても何も出てこない。
おそらく「Spanのタイミングで出力されない」というのがこれなんだろう。

* [Spanのタイミングでログ出力したい](https://zenn.dev/scirexs/articles/c467a911218593#span%E3%81%AE%E3%82%BF%E3%82%A4%E3%83%9F%E3%83%B3%E3%82%B0%E3%81%A7%E3%83%AD%E3%82%B0%E5%87%BA%E5%8A%9B%E3%81%97%E3%81%9F%E3%81%84)

```toml
[dependencies]
anyhow = "1.0.104"
tokio = { version = "1.0", features = ["full"] }
tracing = "0.1.44"
tracing-subscriber = "0.3.23"
```

```rust
use tracing::*;

async fn hogege(val: u32) -> u32 {
    // trace!("val: {val}");
    12 * val
}

#[instrument(fields(id = 123456))]
async fn hoge(val: u32) -> u32 {
    // trace!("val: {val}");
    hogege(val).await
}

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::Subscriber::builder()
        .with_line_number(true)
        .with_max_level(tracing::Level::TRACE)
        .init();

    info!("first");
    info!("value: {}", hoge(3).await);

    Ok(())
}
```

```log
2026-08-17T11:48:39.800176Z  INFO hello: 22: value: 36
```

`hoge()`と`hogege()`でコメントアウトしている`trace!()`を戻すと相応のログは出力される。

## spanを後から設定

`hoge()`で`#[instrument(fields(id = 123456))]`とspanの値を固定にしていたが、
実行中に値を書き換えたという場合を見てみよう。

```rust
use tracing::*;

async fn hogege(val: u32) -> u32 {
    trace!("val: {val}");
    12 * val
}

#[instrument(fields(val = field::Empty))]
async fn hoge(val: u32) -> u32 {
    Span::current().record("val", &val);
    trace!("val: {val}");
    hogege(val).await
}

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::Subscriber::builder()
        .with_line_number(true)
        .with_max_level(tracing::Level::TRACE)
        .init();

    info!("first");
    for _i in 0u32..3 {
       info!("value: {}", hoge(3).await);
    }

    Ok(())
}
```

これも3回同じ出力が行われるだけだ。

## ループの中にSpan::current().record

では`for`の位置を`main()`から`hoge()`に移動させ、ループの中で`Span::current().record`を呼び出してみよう。

```rust
use tracing::*;

async fn hogege(val: u32) -> u32 {
    trace!("val: {val}");
    12 * val
}

#[instrument(fields(val = field::Empty))]
async fn hoge(val: u32) -> u32 {
    for _i in 0u32..3 {
        Span::current().record("val", &val);
        trace!("val: {val}");
        hogege(val).await;
    }
    hogege(val).await
}

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::Subscriber::builder()
        .with_line_number(true)
        .with_max_level(tracing::Level::TRACE)
        .init();

    info!("first");
    info!("value: {}", hoge(3).await);

    Ok(())
}
```

これはspanが蓄積するというか、階層が潜るというか、そういう動作になってしまう。  
ループの先頭に戻るときにスコープが解除されてspanも消えそうな気がするのだが、そうはならないようだ。

### ループの中でspanをつくるのはよいがこれは非推奨

いろいろ試したが、ループの中でspanを作れば潜らずに済んだ。
`info_span!()`を使っているが、これはspanのレベルがINFOなだけでログ出力のeventのレベルとは関係ないそうだ。
まだ試していないが、eventのレベルがいつもの`info!()`や`trace!()`に効いてくるレベルで、
spanのレベルはspan出力の方に効いてくるのだと思う。

* [Core concepts](https://docs.rs/tracing/0.1.44/tracing/#core-concepts)

```rust
use tracing::*;

async fn hogege(val: u32) -> u32 {
    trace!("val: {val}");
    12 * val
}

async fn hoge(val: u32) -> u32 {
    for _i in 0u32..3 {
        let span = info_span!("my_span", val = field::Empty);
        let _guard = span.enter();
        span.record("val", &val);
        trace!("val: {val}");
        hogege(val).await;
    }
    hogege(val).await
}

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::Subscriber::builder()
        .with_line_number(true)
        .with_max_level(tracing::Level::TRACE)
        .init();

    info!("first");
    info!("value: {}", hoge(3).await);

    Ok(())
}
```

```log

2026-08-17T12:29:14.691407Z TRACE my_span{val=3}: hello: 13: val: 3
2026-08-17T12:29:14.691432Z TRACE my_span{val=3}: hello: 4: val: 3
2026-08-17T12:29:14.691472Z TRACE my_span{val=3}: hello: 13: val: 3
2026-08-17T12:29:14.691494Z TRACE my_span{val=3}: hello: 4: val: 3
2026-08-17T12:29:14.691534Z TRACE my_span{val=3}: hello: 13: val: 3
2026-08-17T12:29:14.691557Z TRACE my_span{val=3}: hello: 4: val: 3
```

分かりづらいので`hoge()`を少し変更。

```rust
async fn hoge(val: u32) -> u32 {
    for i in 0u32..3 {
        let span = info_span!("my_span", val = field::Empty, i = field::Empty);
        let _guard = span.enter();
        span.record("val", &val);
        span.record("i", &i);
        trace!("val: {val}");
        hogege(val).await;
    }
    hogege(val).await
}
```

これなら`i`が更新されているし、階層になっていないのもわかるだろう。

ただ、Devin Desktopに質問すると`.await`をまたぐ`_guard`は非推奨とのことだ。
spanは`tokio::spawn()`などで同じタスクが複数作られたときに見分けたりするのに使う「分散トレーシング」向けなので、
ちょっとログ出力を簡略して書きたいなあ、みたいな用途ではないそうなのだ。

### JSON風に

`trace!()`などは`println!()`のようにフォーマットを書くだけでなく、最初の方にフィールド値として
`trace!(loop = i, value = val, "val: {val}");` のように列挙することもできる。  
デフォルトのフォーマットだと、先にメッセージ部分が出力され、その後にフィールド値が出力される。

```log
TRACE hello: 10: val: 3 loop=1 value=3
```

個人的にはちょっと見づらいかなあ。  
JSONフォーマットならフォーマッタをカスタマイズしなくてもできるそうだ。

```toml
tracing-subscriber = { version = "0.3.23", features = ["json"] }
```

```rust
    tracing_subscriber::fmt()
        .with_line_number(true)
        .with_max_level(tracing::Level::TRACE)
        .json()
        .init();
```

これが見やすいのかどうかはわからんが、クラウドのログはNDJSONのようなのでツールなどで解析はしやすいのかも。

```json
{"timestamp":"2026-08-17T14:18:54.109429Z","level":"TRACE","fields":{"message":"val: 3"},"target":"hello","line_number":4}
```

## let _ = span.enter()ではダメ

サンプルコードで`span.enter()`を受け取る変数が`_enter`だの`_guard`だのになっていたが、
特に使うわけでもないし`_`で十分だろう、と思ったらそうではなかった。  
`_`で受け取るとspanが出力されないのだ。

てっきり`_`はプレフィクスの扱いだと思い込んでいたのだが、`_`はまた別の扱いになっていた。  
メモリを確保しないし、行末のセミコロンが来たらdropするようになるのだと。
