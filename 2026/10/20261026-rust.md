SQLiteには日付型という[型](https://sqlite.org/datatype3.html#storageclasses)はない。

* `NULL`
* `INTEGER`
* `REAL`
* `TEXT`
* `BLOB`

BLOBなんてあったっけ？ どれにもあてはまらなかったらTEXTを使うというイメージだったのだが。

そのうちで日付型に使えるのは[この3つ](https://sqlite.org/datatype3.html#date_and_time_datatype)とある。

* `INTEGER`
* `REAL`
* `TEXT`

[time-value型](https://sqlite.org/lang_datefunc.html#tmval)として12パターンがあり、どれかに当てはまればよいのだろう。

* [Date And Time Functions](https://sqlite.org/lang_datefunc.html)

そう言われると、それはそれで悩む。。。  
個人的に扱いやすいのはUNIX EPOCHなのだけど、ユリウス暦もそのフォーマットのようで、modifierを付けるとUNIX EPOCHとして扱うとかなんとか書いてあるので間違うと変なことになりそうだ。  


## rusqliteでの型

* [rusqlite - Rust](https://docs.rs/rusqlite/0.41.0/rusqlite/)

`chrono`か`time`か`jiff`か。使うやつをfeaturesに指定する。  
"modern-full"だと全部入っているから混ぜても問題ないのだろうから、お好みで。  
ここでは`time`を使う。

[自作説明](https://blog.hirokuma.work/langs/rust/db_rusqlite.html)のコードを変更して`time::OffsetDateTime`を使うようにした。  
ついでに、いちいち変換するのが面倒なので`serde_rusqlite::from_row()`を使った。  
`serde_rusqlite`を使う場合のつらいところは、`FromSql`や`ToSql`が使えないところだ。
ここでは`SELECT`で`struct`に読み込ませるほうなのでdeserialize方向。なので`serde::Deserialize`をつけて変換できないフィールドには`deserialize_with`で変換関数を呼び出してもらう。
なので調べてはいないがパフォーマンスは落ちるような気がする。

で、最初はSQLiteの日付フォーマットに合わせ込むやり方が分からず、こんな感じで自分でフォーマット関数を呼び出していた。
自分で書いたような気がしないので`ToSql`からコピーしたとかAIに作ってもらったとかそういうのだろう。

```rust
use anyhow::Result;
use rusqlite::{Connection, named_params};
use serde::Deserialize;
use time::{OffsetDateTime, PrimitiveDateTime, macros::format_description};

#[derive(Debug, Deserialize)]
struct Person {
    id: i32,
    #[serde(deserialize_with = "convert_datetime")]
    created_at: OffsetDateTime,
    name: String,
}

fn main() -> Result<()> {
    let conn = Connection::open_in_memory()?;

    conn.execute(
        "CREATE TABLE person (
            id          INTEGER PRIMARY KEY,
            created_at  TEXT DEFAULT CURRENT_TIMESTAMP,
            name        TEXT NOT NULL
        )",
        (), // empty list of parameters.
    )?;

    let mut stmt = conn.prepare("INSERT INTO person (name) VALUES (:name)")?;
    stmt.execute(named_params! {
        ":name": "yoshio",
    })?;

    let mut stmt = conn.prepare("SELECT * FROM person")?;
    let mut rows = stmt.query([])?;
    let mut people = Vec::new();
    while let Some(row) = rows.next()? {
        let v: Person = serde_rusqlite::from_row(row)?;
        people.push(v);
    }
    for person in people {
        println!("id: {}", person.id);
        println!("  name      : {}", person.name);
        println!("  created_at: {}", person.created_at);
    }
    Ok(())
}

fn convert_datetime<'de, D>(deserializer: D) -> rusqlite::Result<OffsetDateTime, D::Error>
where
    D: serde::Deserializer<'de>,
{
    let s = <String>::deserialize(deserializer)?;
    parse_datetime(&s).map_err(|_| serde::de::Error::custom(format!("invalid datetime: {s}")))
}

fn parse_datetime(s: &str) -> Result<OffsetDateTime> {
    let format = format_description!("[year]-[month]-[day] [hour]:[minute]:[second]");
    let dt = PrimitiveDateTime::parse(s, &format)?;
    Ok(dt.assume_utc())
}
```

さすがに自分でフォーマットは作りたくないなあとAIに相談するとやってくれた。
SQLiteに持っていくから`ToSql`だと思ってたけど`FromSql`なの？  
あと、オリジナルの方はUNIX EPOCHでも変換できるようになっているけどこれは文字列のみだから注意してね、とのこと。
SQLが`TEXT`だからそれでいいのだけど、`INTEGER`だとエラーになるそうだ。

```rust
fn convert_datetime<'de, D>(deserializer: D) -> Result<OffsetDateTime, D::Error>
where
    D: serde::Deserializer<'de>,
{
    let s = String::deserialize(deserializer)?;
    <OffsetDateTime as FromSql>::column_result(ValueRef::Text(s.as_bytes()))
        .map_err(serde::de::Error::custom)
}
```

いやあ、このコードは私には思いつかないね。  
deserializeして`OffsetDateTime`すればよいのだから、文字列がどうのこうのは考えずに`FromSql`で変換すればよいだけなのか。  
`INSERT`などで使うときは`.to_sql()`でよさそう、なんだけど、コンパイルエラーにも実行時エラーにもならず期待と異なる値が使われるだけになったりするのでまだ安心できない。
