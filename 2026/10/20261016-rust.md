`tokio::select!`は`tokio::spawn()`したものの終了チェックに使っていた・・・というかAIかサンプルコードだかで作ってもらったのがそう書いてあったのでそのまま使っていた。  
しかしちょっとした非同期処理で、メソッドが開始前にエラーになったかどうかはこちらを、メソッドが実行中にエラーになったかはこちらを、みたいな紹介をされて、
どちらかで終了判定しないといけないから`tokio::select!`を使いましょう、というアドバイスをされた。AIから。

そ、そのくらいやってやる！と勢い込んだがよくわからず・・・。けっきょくやってもらった。  
悩んでいたのは、`tokio::select!`自体が`.await`みたいな効果を持ちそうなので、呼びたいメソッドの中でも`.await`無しで書かないとダメなんじゃないの？という点だった。
もちろんそんなことはなく、たぶん`select!`の中では`Future`を自分でうまいこと処理することで非同期メソッドのどれかが先に終わったら全部終わらせてるとかじゃないかね。

```toml
[dependencies]
tokio = { version = "1.53.3", features = ["full"] }
```

```rust
#[tokio::main()]
async fn main() {
    tokio::select! {
        _ = loop1() => {},
        _ = loop2() => {},
    }
}

async fn loop1() {
    loop {
        tokio::time::sleep(std::time::Duration::from_secs(3)).await;
        println!("loop1");
    }
}

async fn loop2() {
    loop {
        tokio::time::sleep(std::time::Duration::from_secs(4)).await;
        println!("loop2");
    }
}
```
