開発はほとんどWSL2側で行っている。  
ファイルもそっち側に置いているのだが、WSL2は`/mnt/c`などでWindows側のファイルにもアクセスできる。逆にWindowsからもWSL2のファイルにアクセスできる。  
それがメリットと言えばそうなのだが、最近はAIで自動的にコードを書いてもらうこともあり心配になってきている。

## AIは便利だけど怖いわ

最近はvscodeのextensionでもAgentモードが使えるので、プロジェクトを開いて適当にお願いするとかなりやってくれる。
私は"Cline"を使ってOllama CloudのOpenAI系APIでアクセスしているのだが、なるべく自分で書くもののエラーが起きたり書き換えだったりするとおまかせしてしまうことも増えた。

AIといってもプロジェクトの中しか読まないんだったらまあいいか、と思っていたのだが、サンプルでコードを作って動かしたりするのに`/tmp`にファイルを作ったりしているのを見てしまった。
「AIが言ってきても指示して実行しなければいいやろう」などと甘いことを思っていたのだが、だんだん面倒で Yes を押すマシンと化してしまった自分を見るとこのままでは危ないと思う。  
Windows側にファイルアクセスしなくても困らないのでCドライブなどへアクセスできないようにしたい。

## wsl.conf

`/etc/wsl.conf`という設定ファイルがある。

* [WSL での詳細設定の構成 - Microsoft Learn](https://learn.microsoft.com/ja-jp/windows/wsl/wsl-config)

いっぱい書いてあるが、こういうのこそAIに聞くべし。

[automount](https://learn.microsoft.com/ja-jp/windows/wsl/wsl-config#automount-settings)に`enabled=false`を書くととりあえず自動マウントはなくなる。
ついでに[interop](https://learn.microsoft.com/ja-jp/windows/wsl/wsl-config#interop-settings)も外すといいんじゃないのということだった。

```conf
[automount]
enabled = false

[interop]
enabled = false
appendWindowsPath = false
```

これで立ち上げ直すと`/mnt/`のCドライブなどはディレクトリは残っているがmountはされていなかった。  
完了だ。

そう思っていた。

## vscodeが動かん

そう、これだとvscodeが動かなかったのだ。
動かないというかファイルにアクセスできなくなった。  
"Remote - SSH" extensionの兄弟みたいな"WSL" extensionというやつだったのでてっきりSSHを使っていると思い込んでいたのだが、どうもそうではないらしい。
よくわからないが、Cドライブとつながることでうまくいっているそうだ。なんじゃそりゃ。

まあ、SSHで接続してしまえば完全に切り離せるとは思う。リモートだとそれでやってるしね。
ただアクセスが多いとちょっとうっとうしい感じになったような気がする。SSHで指定しているkeyのパスフレーズを毎回聞いてくるとか。  
まずはどこまで戻せば動くか確認しよう。

automountはやめて手動でCドライブだけマウントさせるようにした。
他にもたくさんWindows側のドライブがあったので、まずは減らして成功するかの確認だ。

```conf
[automount]
enabled = false

[boot]
command = "mkdir -p /mnt/c && mount -t drvfs C: /mnt/c"
```

うむ、動いた。

"interop"の方は別の問題があった。  
いくつかVHDファイルを作ってext4フォーマットしているのを`.bashrc`でマウントさせていたのだが、
このとき`wsl.exe`を直接実行していたのにパスが見つからなかったのだ。  
これはフルパスで`/mnt/c/WINDOWS/system32/wsl.exe`としてやれば動いた。
つまり`wsl.exe`があるCドライブのマウントは外せないのか。

## read-onlyでマウント

とりあえず、間違ってWSL2側からCドライブに書き込むのを防ぐのはできそうだ。
読むのは防げないが破壊は防げるのでは。

```conf
[automount]
enabled = false

[boot]
command = "mkdir -p /mnt/c && mount -t drvfs C: /mnt/c -o ro,uid=1000,gid=1000"
```

おお、成功だ。
vscodeも起動した。

```shell
$ touch /mnt/c/Temp/hello.txt
touch: cannot touch '/mnt/c/Temp/hello.txt': Read-only file system
```

ということは、WSL2から`/mnt/c`に何か書き込んだのをWindows側のvscodeが読み取っているというわけではないのか。
あるいは違う権限で動いているとかWSL2だけのアクセスとかあるのかもしれない。  
いや、そしたら`/mnt/c`が条件というのも変か。ううむ。。。

Geminiはこのサイトを紹介してくれた。  
あー、別にWSLを立てるのね。
