最近、[rusqlite](https://github.com/rusqlite/rusqlite)でSQLiteを扱っていたのだが、
そもそも言語の中に別のスクリプトを書くというのが面倒だし、コンパイルではチェックされないのでエラーが出るのは実行時だし、
SQLに慣れていない私にはとても大変だったのだ。

ORMというものもあるが、あまり使いたくないという気持ちがある。
何かのときにGoだったかTypeScriptだったかで使ったことがある程度なのだが、
バージョン管理しやすくてよいのだけど、私がやるくらいの作業だと「DB消してやり直し」で済ませるか、
SQLiteしか使わないので新しくDBファイルを作って移し替えて削除くらいでいいかなと。  
それ以上の仕事になったら、また考えよう。

その中間で、コンパイル時にある程度チェックできて、でもSQLで書いているくらいの感覚があるというSQLxを調べようと思ったのである。
Goにもsqlxってあったような？ あれ、前回使ったのはそういうやつだったっけ？ 年寄りの記憶はあてにならんな。

## SQLx

* [transact-rs/sqlx: 🧰 The Rust SQL Toolkit. An async, pure Rust SQL crate featuring compile-time checked queries without a DSL. Supports PostgreSQL, MySQL, and SQLite.](https://github.com/transact-rs/sqlx)

インストールする前に、私が期待しているコンパイル時のチェックがどうなっているかを見ておこう。

[Compile-time verification](https://github.com/transact-rs/sqlx#compile-time-verification)によると、`query()`ではなく`query!()`マクロか`query_as!()`マクロを使うそうだ。
なんでもかんでもチェックするわけではないのだ。

また、置き換えれば済むというわけでもなく制約もある。  
開発用データベースがいるらしい。これはオフラインモードというものでキャッシュしておくと使わずに済むそうだが、それがないならコンパイルができないということだろうか。

### featuresが多い

では[インストール](https://github.com/transact-rs/sqlx#install)してみよう。

どうしたいかによって指定するfeaturesが異なる。組み合わせが多い。  
非同期を使う気がなくても"runtime-"系のfeautresは必要なようだ。実行時にエラーになった。

SQLiteの場合は、"sqlite"はbundle版、"sqlite-unbundled"が非bundle版、あとは"sqlite-preupdate-hook"というのがあるのだがリンク先が切れていた。
誰がSQLiteを組み込むかはなかなか面倒な話だ。
私はbdk-walletクレートをしばしば使うが、そちらも内部でrusqliteを使っている(使っているのはbdk-chainだったか)。
あちらはunbundleだけなので組み込みたければ自分でやるのだが、バージョンをどうしようかとか考えると面倒でね。。。

あとは"derive"、"macros"、必要に応じて"uuid"や"chrono"/"time"といったところか。

### DBファイルがいる

SQLiteはin-memoryもファイルもいけるのだが、どうもSQLxでファイルを作る機能はないようだ。
`sqlx-cli`で事前に空ファイルを作る手順になっている。

* [examples/todos](https://github.com/transact-rs/sqlx/blob/03af8bcc5711a1935580a54bea249c219a0c217d/examples/sqlite/todos/README.md#setup)

こんな感じでやってみたのだが"unable to open database file"になってしまった。

```rust
    let pool = SqlitePoolOptions::new()
        .connect("sqlite:./test.db")
        .await?;
```

## サンプル

SQLiteは空ファイルがあれば勝手にやってくれるそうなので、`touch`コマンドで作るだけにした。

```toml
[dependencies]
anyhow = "1.0.104"
sqlx = { version = "0.9.0", features = ["runtime-tokio", "sqlite-unbundled", "derive", "macros", "time"] }
time = "0.3.55"
tokio = { version = "1.0", features = ["full"] }
```

```rust
use sqlx::sqlite::SqlitePoolOptions;

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    let pool = SqlitePoolOptions::new()
        .connect("sqlite:./test.db")
        .await?;
    // 連続でSQLが書ける
    sqlx::raw_sql("
CREATE TABLE IF NOT EXISTS my_table (
    id INTEGER PRIMARY KEY,
    created_at DATETIME,
    name TEXT
);
INSERT INTO my_table (id, created_at, name) VALUES (1, datetime('now'), 'John Doe')
        ")
        .execute(&pool)
        .await?;
    let row: (i64, String, String) = sqlx::query_as("SELECT * FROM my_table WHERE id = ?")
        .bind(1)
        .fetch_one(&pool)
        .await?;
    println!("row: {:#?}", row);
    Ok(())
}
```

```shell
$ rm -f test.db
$ touch test.db
$ cargo run
row: (
    1,
    "2026-09-05 03:50:49",
    "John Doe",
)
```

`let row: (i64, time::OffsetDateTime, String)`にするとこうなる。

```shell
row: (
    1,
    2026-09-05 3:56:55.0 +00:00:00,
    "John Doe",
)
```

## チェックするマクロはDATABASE_URLがいる

やっぱり`query!`や`query_as!`があると`DATABASE_URL`がなくてはビルドに失敗した。  
vscodeだと`.vscode/settings`に書くこともできるらしいが、起動時しか読み込まないので再設定したら再起動がいる。
それよりは`.env`に書いたほうが楽そうだ。

問題は他にもある。
ここで使っている`test.db`へはプログラム中で`CREATE TABLE`しているのだが、
このチェックするマクロはSQLへの書き込みなどはしないもののテーブル定義の存在はDBから取ってくるようである。  
つまり、このプログラムを新規ではチェックできないのだ。。。
やるなら`CREATE TABLE`で一度止めたプログラムを実行し、そのあとでチェックマクロの部分もビルドできるようにするとか。  
SQLの文法をチェックしてくれるなんてありがたいと思っていたが、SQLiteみたいに手軽に`CREATE TABLE`するタイプではやりづらい。

となると、マクロを使う＝DBテーブルは最初から用意しておく、になるのだろう。
チェックしてくれる代償といえば響きは良いが、面倒は面倒だ。
そうなると[オフラインモード](https://github.com/transact-rs/sqlx/blob/03af8bcc5711a1935580a54bea249c219a0c217d/sqlx-cli/README.md#enable-building-in-offline-mode-with-query)の使い方も覚えておきたい。

## オフラインモード

まず、現在ビルドできないけど動くはずなコードを載せておく。
先ほどのコードを`query_as!`に差し替え、`struct`を用意して軽く合わせただけだ。
`.env`ファイルはプロジェクトのルートディレクトリに置いている。  
エラーは、`test.db`がなければ"error returned from database: (code: 14) unable to open database file"、
空ファイルだけあれば"error returned from database: (code: 1) no such table: my_table"だ。


```env
DATABASE_URL="sqlite:./test.db"
```

```rust
use sqlx::sqlite::SqlitePoolOptions;

#[allow(unused)]
#[derive(Debug, sqlx::FromRow)]
struct MyTable {
    id: i64,
    created_at: Option<time::OffsetDateTime>,
    name: Option<String>,
}

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    let pool = SqlitePoolOptions::new()
        .connect("sqlite:./test.db")
        .await?;
    // 連続でSQLが書ける
    sqlx::raw_sql("
CREATE TABLE IF NOT EXISTS my_table (
    id INTEGER PRIMARY KEY,
    created_at DATETIME,
    name TEXT
);
INSERT INTO my_table (id, created_at, name) VALUES (1, datetime('now'), 'John Doe')
        ")
        .execute(&pool)
        .await?;
    let rows = sqlx::query_as!(MyTable, "SELECT * FROM my_table")
        .fetch_all(&pool)
        .await?;
    println!("rows: {:#?}", rows);
    Ok(())
}
```

### CLIコマンドのインストール

まずは[コマンドのインストール](https://github.com/transact-rs/sqlx/blob/03af8bcc5711a1935580a54bea249c219a0c217d/sqlx-cli/README.md#with-rust-toolchain)が必要だ。
全部載せ以外にDBバックエンドごとへ対応したインストールもできるようだ。`Cargo.toml`へのfeautres指定と同じようなパラメータだが、個別にしないといけないような理由はなんだろうか？
サイズが大きすぎるとか？

Claude(無料)に質問したところ、cliコマンドのビルド時間が短縮されることと、その分サイズが減るのがメリット。
その代わり他のDB環境向けには使えないので、それをメリットと捉えるかどうかというところだった。  
いまのところSQLiteしか使う予定がないし、SQLiteがインストールされた環境でしか作業しないので載っていた例からsqlite-unbundledのやつをそのまま使った。

```shell
$ cargo install sqlx-cli --no-default-features --features sqlite-unbundled
```

### エラーになる

さて、今の状況はこうである。

* `test.db`は無い
* カレントディレクトリの`.env`に`DATABASE_URL`が設定してある

いきなりオフラインモードのコマンドが使えるのだろうか？  
ダメだった。

```shell
$ cargo sqlx prepare
error: error returned from database: (code: 14) unable to open database file
```

ならばDBを準備するコマンドを実行すればよいのか？  
ダメだった。
オフラインモードにするためにはDBテーブルがいるのだ。

このくらいのプログラムであれば`CREATE TABLE`だけ引っこ抜いてもよいし、`CREATE TABLE`だけ実行して終了するように変更するのも簡単なのだけど、
やっぱりコード中で`CREATE TABLE`するタイプのプログラムとSQLxのチェックマクロは相性が悪いのでどうしようもなさそうだ。

$ echo "CREATE TABLE IF NOT EXISTS my_table (id INTEGER PRIMARY KEY, created_at DATETIME, name TEXT)" | sqlite3 test.db
$ cargo sqlx prepare

`.sqls/`ができた。ここでビルドすると成功する。
vscodeを使っていたのでrust-analyzerをRestartすると、そちらもエラーが消えた。

```shell
$ cargo build
$ 
```

では`test.db`がなくなっても大丈夫だろうか？
ダメだった。`SQLX_OFFLINE=true`がいるらしい。

```shell
$ mv test.db _test.db
$ cargo clean
$ cargo build
エラーいろいろ

$ cargo sqlx prepare --check
error: error returned from database: (code: 14) unable to open database file

$ SQLX_OFFLINE=true cargo build
$
```

`.env`に`SQLX_OFFLINE=true`があればvscodeでもエラー表示にならなくなった。
`.sqlx/xxxx.json`の中身はDBテーブルを調べたような感じだったので、`CREATE TABLE`があれば作ることができそうな気がする。
ああでも複数テーブルあるとそれだけで面倒だな。。。

なんとなくSQLテーブルの管理もORMの仕事かと思っていたのだが、migrationっていうやつはSQL界では昔からある概念というか管理方法なのだろうね。

## CREATE TABLEを外に出す

SQLiteは組み込み型DBなので`CREATE TABLE`もアプリに組み込んでしまいたい。
なんとかならんかと続けてClaude(無料)に質問すると、`query_file!`マクロがよいでしょうとのこと。
まあ、最初はRust標準の`include_str!`で読み込めばいいでしょうという回答を真に受け、しかし`query!`はリテラルしか受け付けないマクロなのでダメだったんだがね。
「前回触れましたが..」とかいうんだったら最初から`include_str!`なんか紹介するんじゃあない、と思ったのは仕方なかろう。

SQLの`CREATE TABLE`と`INSERT INTO`を別のファイルにして読み込むようにし、もう一度`cargo sqlx prepare`でJSONを作り直すとエラーが無くなった。
その前に`cat sql/my_table.sql | sqlite3 test.db`で一応DBファイルを作った。

```rust
use sqlx::sqlite::SqlitePoolOptions;

#[allow(unused)]
#[derive(Debug, sqlx::FromRow)]
struct MyTable {
    id: i64,
    created_at: Option<time::OffsetDateTime>,
    name: Option<String>,
}

#[tokio::main()]
async fn main() -> anyhow::Result<()> {
    let pool = SqlitePoolOptions::new()
        .connect("sqlite:./test.db")
        .await?;
    let mut conn = pool.acquire().await?;
    sqlx::query_file!("./sql/my_table.sql")
        .execute(&mut *conn)
        .await?;
    sqlx::query_file!("./sql/default_data.sql")
        .execute(&mut *conn)
        .await?;
    let rows = sqlx::query_as!(MyTable, "SELECT * FROM my_table")
        .fetch_all(&pool)
        .await?;
    println!("rows: {:#?}", rows);
    Ok(())
}
```

`cargo sqlx prepare`でJSONを作り直したが、このファイルはマクロごとに作られるのだな。
このプログラムだと3ファイル作られた。
作り直すときは毎回`.env`から`SQLX_OFFLINE=true`をコメントアウトするので、そこは面倒さを感じるかもしれない。
