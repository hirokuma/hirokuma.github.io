私は`tracing`を使うことが多いので、その例だけ示す。"Case 1"になる。

## tracingログ

`setup_default_user_utils()`の後でないと有効にならない。
`flutter_rust_bridge`にfeaturesを足しておかねば出てこないと思う。

```toml
[dependencies]
flutter_rust_bridge = { version = "=2.13.0", features = ["log"] }
```

`log`クレートはログ出力本体ではないのでそこに流し込むことができればなんでもよい。
もちろん`tracing`でもよい。

```toml
tracing = {version = "0.1.44", features = ["log"]}
```

```rust
#[flutter_rust_bridge::frb(init)]
pub fn init_app() {
    flutter_rust_bridge::setup_default_user_utils();

    // log sample
    error!("log: error");
    warn!("log: warning");
    info!("log: info");
    debug!("log: debug");
    trace!("log: trace");
}
```

## ログレベルの変更

`setup_default_user_utils()`は[こういうコード](https://github.com/fzyzcjy/flutter_rust_bridge/blob/0876e2ebd91e2dd195978a42e7ce15e054dc5854/frb_rust/src/misc/user_utils.rs#L5-L10)になっていた。
デフォルトのログレベルはTraceになっている。

```rust
pub fn setup_default_user_utils() {
    // setup log before others, such that we can see logs in other setup functions
    #[cfg(feature = "log")]
    setup_log_to_console(log::LevelFilter::Trace);
    setup_backtrace();
}
```

ログレベルを変更したかったら、この中身を自分のinit関数で呼ぶのが良いだろう。
featureは、もともとログ出力するつもりで`Cargo.toml`を書いているのでわざわざ追加しなくてもよいかな。
出力したくなければflutter_rust_bridgeの"log"を外してしまえばよいのだ。

```rust
pub fn init_app() {
    flutter_rust_bridge::setup_log_to_console(log::LevelFilter::Info);
    flutter_rust_bridge::setup_backtrace();
```

引数に`log::`を使っているので`Cargo.toml`に追加しておこう。

```toml
log = "0.4.34"
```

## Androidでモジュールごとにレベル付け

tracing-subscriberではモジュールごとにログレベルの設定ができて便利だ。
Androidだと`android_logger`というものを使って同じことができるそうだ。

AIにやってもらったんでそっちに依頼したほうが早いと思うが、できると思わなかったら指示も出さないだろうからね。

```toml
[target.'cfg(target_os = "android")'.dependencies]
android_logger = "0.15"
```

設定は大体こんな感じ。`.parse()`の中にtracing-subscriberのフォーマットで書いておけばよいそうだ。

```rust
    #[cfg(target_os = "android")]
    {
        use android_logger::{Config, FilterBuilder};
        let _ = android_logger::init_once(
            Config::default()
                .with_max_level(log::LevelFilter::Trace)
                .with_filter(
                    FilterBuilder::new()
                        .parse("info,alloy_transport_http=warn,hogehoge=trace,fugafuga=warn")
                        .build(),
                ),
        );
    }
    #[cfg(not(target_os = "android"))]
    flutter_rust_bridge::setup_log_to_console(log::LevelFilter::Trace);
```

`D/hogehoge` や `I/fugafuga` のようなlogcatっぽい出力になるのでわかりやすい。  
frbのコマンドでプロジェクトを作った`rust/api`はパッケージ名が`rust_lib_<アプリ名>`になるようなので注意というほどではないけど間違えないようにしよう。
