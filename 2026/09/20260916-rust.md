AIにコードを作ってもらってよかったなと思うのは、自分が知らない技を見せてくれるところだ。
今も`Option<T>`に`.map()`するという技を見て、そういうこともできるんだと思ったところだ。

まだコードを見ただけで動かしていないのでサンプルコードで試しておこう。

## mapしても変換されない?

予想では`v`が`i32`とかになる、だったのだが。。。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.map(|k| k);
    println!("v: {:?}", v);
    let w = b.map(|k| k);
    println!("w: {:?}", w);
}
```

結果としては`Option<i32>`が維持されていた。
`w`も`None`のままだし、`.map`しても変換されない・・・？

```log
v: Some(10)
w: None
```

## 変換すると中身が変換される

AIが作ったコードは`.map`の中で`to_string()`して文字変換していたのでまねしてみよう。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.map(|k| k.to_string());
    println!("v: {:?}", v);
    let w = b.map(|k| k);
    println!("w: {:?}", w);
}
```

結果はこう。
なるほど、`Option`の部分はそのままで`T`だけが変換されるのね。
まあそうじゃないと`None`をどうするって話になるか。

```log
v: Some("10")
w: None
```

## オライリーの本にあったわ

そういえばこの変換は以前購入したオライリーさんの「Effective Rust」の図に載ってたわ。
`Option<T>`から`Option<U>`への変換だ。

図にはもう1つ`and(_then)`が載っていたのでそちらも確認しておこう。

## andでの変換

`.and`は変換というか、`.is_some()`のような印象を受けた。  
`.map`だとクロージャで値を受け取って別の値にできるのだが、`.and`は受け取らずに値があればいい、みたいな挙動だ。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.and(Some("20"));
    println!("v: {:?}", v);
    let w = b.and(Some("30"));
    println!("w: {:?}", w);
}
```

なので`b`の方は`.and`を通らず`None`のままになっている。

```log
v: Some("20")
w: None
```

### and_thenもあるよ

vscodeで書いていたのだが、`.and`を`.and_then`にしようとひたすら補完してきた。
雰囲気としてはクロージャを取るところは`.map`に近いと思う。
ただクロージャの中で返す値は`Option<U>`にしないといけない。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.and_then(|k| Some((k * 2).to_string()));
    println!("v: {:?}", v);
    let w = b.and_then(|k| Some((k * 2).to_string()));
    println!("w: {:?}", w);
}
```

結果はこう。もちろん`Option<T>`を`Option<T>`のまま返しても良い。

```log
v: Some("20")
w: None
```

中のメソッドで戻り値が`Option<U>`を返すタイプだと`.map`だったらクロージャの中で`Option`を外さないといけないが`.and_then`ならそれが不要、くらいの使いわけで良さそうだ。
