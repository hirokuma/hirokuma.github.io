AIにコードを作ってもらってよかったなと思うのは、自分が知らない技を見せてくれるところだ。
今も`Option<T>`に`.map()`するという技を見て、そういうこともできるんだと思ったところだ。

まだコードを見ただけで動かしていないのでサンプルコードで試しておこう。

## Option.mapしても変換されない?

予想では`v`が`i32`とかになる、だったのだが。。。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.map(|k| k);
    println!("v: {:?}", v);
    let w = b.map(|k| k);
    println!("w: {:?}", w);
}
```

結果としては`Option<i32>`が維持されていた。
`w`も`None`のままだし、`.map`しても変換されない・・・？

```log
v: Some(10)
w: None
```

## Option.mapすると中身が変換される

AIが作ったコードは`.map`の中で`to_string()`して文字変換していたのでまねしてみよう。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.map(|k| k.to_string());
    println!("v: {:?}", v);
    let w = b.map(|k| k);
    println!("w: {:?}", w);
}
```

結果はこう。
なるほど、`Option`の部分はそのままで`T`だけが変換されるのね。
まあそうじゃないと`None`をどうするって話になるか。

```log
v: Some("10")
w: None
```

## オライリーの本にあったわ

そういえばこの変換は以前購入したオライリーさんの「Effective Rust」の図に載ってたわ。
`Option<T>`から`Option<U>`への変換だ。

図にはもう1つ`and(_then)`が載っていたのでそちらも確認しておこう。

## andでの変換

`.and`は変換というか、`.is_some()`のような印象を受けた。  
`.map`だとクロージャで値を受け取って別の値にできるのだが、`.and`は受け取らずに値があればいい、みたいな挙動だ。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.and(Some("20"));
    println!("v: {:?}", v);
    let w = b.and(Some("30"));
    println!("w: {:?}", w);
}
```

なので`b`の方は`.and`を通らず`None`のままになっている。

```log
v: Some("20")
w: None
```

### and_thenもあるよ

vscodeで書いていたのだが、`.and`を`.and_then`にしようとひたすら補完してきた。
雰囲気としてはクロージャを取るところは`.map`に近いと思う。
ただクロージャの中で返す値は`Option<U>`にしないといけない。

```rust
fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    let v = a.and_then(|k| Some((k * 2).to_string()));
    println!("v: {:?}", v);
    let w = b.and_then(|k| Some((k * 2).to_string()));
    println!("w: {:?}", w);
}
```

結果はこう。もちろん`Option<T>`を`Option<T>`のまま返しても良い。

```log
v: Some("20")
w: None
```

中のメソッドで戻り値が`Option<U>`を返すタイプだと`.map`だったらクロージャの中で`Option`を外さないといけないが`.and_then`ならそれが不要、くらいの使いわけで良さそうだ。

## Option.map_or_else

`Option<T>`の`T`が構造体だった場合、`None`じゃなかったら中の値を使い、`None`だったら適当な値を使おうということもある。
そういう場合は`.map_or_else`がよろしい。  
間違えそうだけど最初のクロージャが`None`のとき、次のクロージャが値があるときだ。

`.as_ref()`しているのは値をmoveさせたくなかったからだ。その代わりというかクロージャの方で`.clone()`している。

```rust
#[derive(Debug)]
struct Abc {
    abc: String,
}

fn main() {
    let abc = Abc { abc: "Hello, World!".into() };
    println!("Abc: {}", abc.abc);

    let def: Option<Abc> = None;
    let g = def.as_ref().map_or_else(|| "None".to_owned(), |value| value.abc.clone());
    println!("{:?}", def);
    println!("G: {}", g);
}
```

不要な`.clone()`は消し忘れがちなのだが、`cargo clippy`のデフォルトでは出てこない。

```shell
$ cargo clippy -- -W clippy::redundant_clone -W clippy::clone_on_copy
```

```toml
[lints.clippy]
redundant_clone = "warn"
clone_on_copy = "warn"
```

### Option.map_orは？

`.map_or_else(Noneクロージャ, Someクロージャ)`はどちらもクロージャを呼び出す。  
では`.map_or`はというと、`.map_or(Noneでの値, Someクロージャ)`っぽい。

```rust
    let g = def.as_ref().map_or("None".to_owned(), |value| value.abc.clone());
```

本当か？ わたし間違ってないか？ でも"default result"か"apply function"なのでそうなのか。

* [map_or](https://doc.rust-lang.org/std/option/enum.Option.html#method.map_or)

`None`のときに計算した値が使えないということだろう。パフォーマンスがちょっと良くなるのかな。
