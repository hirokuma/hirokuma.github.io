flutter_rust_bridgeで、Rust側でのエラー処理を扱おうとしている。

コンソールアプリでは`anyhow::Result<T>`を使っていたので同じように`anyhow::Result`を返すようなインターフェースにしていた。
Flutter側ではtry-catchの`catch(e)`で捕まえられるのでログに出したところこんな感じになっていた。

```log
AnyhowException(自分のエラーメッセージ

1: <unknown>
2: <unknown>
......
```

[AnyhowException](https://pub.dev/documentation/flutter_rust_bridge/latest/flutter_rust_bridge/AnyhowException-class.html)になるのはよいのだが、私が見たいメッセージに加えていろいろ追加されている。

## たぶんanyhow::Resultで返さないほうが良い

Rust側で`anyhow::Result<T>`から`std::result::Result<T, String>`として文字列として返すと`catch(e)`の`e`は文字列だけになったのでまだこちらのほうが扱いやすい。  
いろいろ考えると言語切替をアプリでやるだろうから、Rustではメッセージは付属データくらいに考えておかねばなるまい。
Rust側で文言を作ってもよいのだろうけど、いちいちビルドし直さないといかんし面倒だろう。

そうなると`enum`にするとかそれぞれの`Error`を作るとか手段はありそうだが、とにかく`anyhow::Result`だと扱いづらかった。
`if (e.runtimeType == AnyhowException)`みたいな書き方で分岐はできるので、1行目だけ引っこ抜いて"AnyhowException("を取り除くとかやれば取れなくはないのだが、なんだかねぇ。

Rustでこういう返し方をすると`WrapperError.myError(field0: エラー文字)`のような扱われ方をしていた。

```rust
pub enum WrapperError {
    MyError(String),
    MyError2(String),
}

impl あああ {
  pub async fn ほげえ(あああ) -> std::result::Result<Self, WrapperError> {
    ......
```

Dartだとこうなっていた。
`if (e.runtimeType == WrapperError_MyError)`のように`enum`名とフィールド名をアンダーバーでつないだ型名になるのかね。

```dart
@freezed
sealed class WrapperError with _$WrapperError implements FrbException {
  const WrapperError._();

  const factory WrapperError.myError(String field0) = WrapperError_MyError;
  const factory WrapperError.myError2(String field0) = WrapperError_MyError2;
}

......

@override
String toString() {
    return 'WrapperError.myError(field0: $field0)';
}
```

扱うときは`is`を使うと良いらしい。

```dart
      if (e is WrapperError_MyError) {
        debugPrint('msg= ${e.field0}');
      }
```

## wrap層を専用で用意するのが良いか

コンソールアプリなどで使っているメソッドをそのままDartに提供するよりも、その手前にwrap層を作ってそこで変換するやり方がいいんじゃなかろうか。  
前回書いた`frb(mirror)`のように無理やりコードを持ってくるようなのもwrap層なら仕方ないと諦められそうだ。
