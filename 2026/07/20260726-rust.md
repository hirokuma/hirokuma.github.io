前回、Rustでrusqliteを使ってSQLiteのSQLを動的に作ることについて考えていた。

* [rust: rusqliteで動的にSQL文を作ってほしい - hiro99ma blog](https://blog.hirokuma.work/2026/07/20260722-rust.html)

いろいろ考えたが、[sqlx](https://github.com/transact-rs/sqlx)を使ってみようかと思う。  
[SeaORMを使う](https://sqlx.dev/#seaorm)というのもあるようだが、まだ私には早かろう。
自分でSQLを書きたくないという点で非常に魅力的なのだが、SQLがどうなるかの予想も付かないようではかえって手間がかかりそうだ。

## sqlxとrusqilteの共存

sqlxを使いたいのはBitcoin関係のアプリで、そこにはbdk_walletを使っている。
bdk_walletはbdk_chainを使っていて、bdk_chainがrusqliteを使うようになっている([SQLite Database](https://bitcoindevkit.github.io/book-of-bdk/cookbook/persistence/sqlite/)の場合)。

気になるのは、sqlxは明示的には他のクレートを追加しなくてもSQLiteを使うことができたという点である。
今の私の環境にはSQLite3がインストールされているので、それが使われたのだろうとは思うがsqlxの中ではどう処理しているのか。

### SQLiteの事情

現在のSQLite最新版はv3.53.4。

* [SQLite Release 3.53.4 On 2026-07-24](https://sqlite.org/releaselog/3_53_4.html)

[リリース状況](https://sqlite.org/changes.html)を見ると月に1,2回はアップデートが行われるようだ。
なのでBreaking Changesや自分が困っているバグが修正されるというようなとき以外はそこまで積極的にアップデートしなくても動作上は困らないのではなかろうか。
そこら辺は使う人の判断でお願いします。

### rusqliteの事情

rusqliteには"bundled" featureがあり、指定していなければシステムのSQLiteが、指定されていれば自分でSQLiteをビルドして組み込む。
組み込めば、システム側に存在しなかったり、何かバージョンの違いによって生じる不具合の可能性などを気にしなくて済む。

> "bundled" uses a bundled version of SQLite. This is a good option for cases where linking to SQLite is complicated, such as Windows.

ただdependenciesしているクレートの中でそれぞれが好き勝手に"bundled"するとそれはそれで同じバイナリの中で衝突してしまうので、
bundledにするのはアプリ側だけにしましょう、というような事が書いてある。めんどうならAIに読んでもらうと良い。私はそうした。

* [Notes on building rusqlite and libsqlite3-sys](https://github.com/rusqlite/rusqlite#notes-on-building-rusqlite-and-libsqlite3-sys)

rusqliteの中で実体のSQLiteの仲介的なことをしているのが`libsqlite3-sys`ということだ。

bdk_walletを使っていて、アプリではSQLiteを直接扱わない場合で"bundled"にしたい場合は、アプリの方でdependenciesに追加すればよいそうだ。
このときrusqliteを追加するのもよいし、libsqlite3-sysを追加するのでもよいそうだ。  
sqlxを使うのであればlibsqlite3-sysの方がよさそうだ。

### sqlxの事情

sqlx自体はSQLite専用というわけではないので、SQLiteで使いたいときはfeaturesに"sqlite"と書く。  
SQLiteの本体とのつなぎ込みについては[featuresの説明](https://github.com/transact-rs/sqlx/tree/1d674f51581598f55436451d5b4b73100cae0b56#cargo-feature-flags)にもあり、rusqliteのREADMEを読めとある。
つまり同じくlibsqlite3-sysを使っているということだろう。

これを書いている時点で[sqlx v0.9.0](https://docs.rs/sqlx/0.9.0/sqlx/)が最新。  
`Cargo.toml`によれば[libsqlite3-sys v0.37.0](https://github.com/transact-rs/sqlx/blob/v0.9.0/Cargo.toml#L252)を使っている。

[bdk_wallet v3.1.0](https://docs.rs/bdk_wallet/3.1.0/bdk_wallet/)では[bdk_chain v0.23.3](https://docs.rs/bdk_chain/0.23.3/bdk_chain/)を使っていて、
そこでは[rusqlite v0.31.0](https://docs.rs/rusqlite/0.31.0/rusqlite/)を使っており、
[libsqlite3-sys v0.28.0](https://docs.rs/libsqlite3-sys/0.28.0/libsqlite3_sys/)を使っている。

sqlxの最新が使いたいというわけではないが、`libsqlite3-sys`のバージョンがこれだけ違うとさすがに不安である。

### libsqlite3-sysの事情

`libsqlite3-sys`はrusqliteのリポジトリの中にあるクレートである。
なのでrusqliteの最新版が持つ`libsqlite3-sys`もまた最新版である。

* [Supported SQLite Versions - rusqlite v0.40.1](https://github.com/rusqlite/rusqlite/tree/v0.40.1/libsqlite3-sys#supported-sqlite-versions) - 最新版
  * [libsqlite3-sys v0.38.1](https://github.com/rusqlite/rusqlite/blob/v0.40.1/libsqlite3-sys/Cargo.toml#L3)
    * The base rusqlite package supports SQLite version 3.34.1 or newer

* [bdk_wallet v3.1.0](https://docs.rs/bdk_wallet/3.1.0/bdk_wallet/)
  * [bdk_chain v0.23.3](https://docs.rs/bdk_chain/0.23.3/bdk_chain/)
    * [rusqlite v0.31.0](https://docs.rs/rusqlite/0.31.0/rusqlite/)
      * [libsqlite3-sys v0.28.0](https://docs.rs/libsqlite3-sys/0.28.0/libsqlite3_sys/)
        * The base rusqlite package supports SQLite version 3.14.0 or newer

* [sqlx v0.9.0](https://docs.rs/sqlx/0.9.0/sqlx/)
  * [libsqlite3-sys v0.37.0](https://docs.rs/libsqlite3-sys/0.37.0/libsqlite3_sys/)
    * [rudqlite v0.39.0](https://github.com/rusqlite/rusqlite/tree/v0.39.0/libsqlite3-sys)
      * The base rusqlite package supports SQLite version 3.34.1 or newer

`libsqlite3-sys`がどのSQLiteバージョンに対応しているかというよりも、親であるrusqliteがどのバージョンに対応しているかということのように見える。  
またbundledにしなければシステムのSQLite3を使うし、sqlxはrusqliteを使っていない。


* SQLite3自体のバージョンはよほどのことがなければ最新版でよい
* `libsqlite3-sys`を"bundled"にしなければ組み込んである`sqlite3.c`などをコンパイルしない
  * [v0.40.0→v0.40.1の差分](https://github.com/rusqlite/rusqlite/compare/v0.40.0...v0.40.1)も`libsqlite3-sys`については機械的な差分でCソースやビルド関係だけのように見える。
* bdk_walletが使うrusqliteのバージョンは勝手に変更できないだろう

ということからすると、sqlxを使いつつbdk_walletも使うならこんな感じか。

* SQLite3のバージョンはシステム側で調整する
* アプリでは`libsqlite3-sys`について"bundeled"を付けない

### SQLite3を同梱したい場合

どうしても同梱したい場合はアプリの`libsqlite3-sys`だけ最新にして"bundled"をつければよいかと思ったが、Geminiいわくそれは無理とのこと。  
`libsqlite3-sys`のバージョンがそれぞれのクレートで非互換と判断される違いになっていて、
そうなると"bundled"の条件は共有されずにそれぞれのクレートがそれぞれの`libsqlite3-sys`をビルドしてリンクしようとする。
アプリは静的に、クレートたちは動的に。
Cargoがネイティブライブラリをリンクする場合、複数バージョンあるようなのは許していないそうでエラーになるそうだ。

実際にビルドさせるところまで持っていくのが面倒なので試していないが、ストーリーとしては理解できる。
"bundled"にしたいなら全クレートで`libsqlite3-sys`のバージョンを合わせよ、ということになるか。

同梱するとインストールする手間は省くことができるが、そこまでするほどではないんじゃなかろうかと思う。
`libsqlite3.so`などを同一ディレクトリにおいて`LD_LIBRARY_PATH=.`などとして実行すれば済むんじゃなかろうかね。  
`LD_LIBRARY_PATH`はちょっと。。。というようであればビルド時に`rpath`で実行ファイルに検索パスを埋め込めばよいそうだ。

```toml
# .cargo/config.toml
[target.x86_64-unknown-linux-gnu]
rustflags = ["-C", "link-arg=-Wl,-rpath,$ORIGIN"]
```
