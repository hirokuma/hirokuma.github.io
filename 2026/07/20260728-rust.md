未だにRustで書いていてなんだかわからないということがある。  
今日はClaudeさんに助けてもらって何とかなったが、説明されても全然わからなかった。
メモしておこう。

## やりたかったこと

Bitcoinの`bdk_wallet`とSQLiteの`rusqlite`を使っていた。
DBの中身をSELECT文で出力し、それを使ってBitcoinに変更が必要な処理を行う、という感じ。

* `bdk_wallet`と`rusqlite`は同じ`struct A`に入れ込んだ
* そのインスタンスを`Arc<Mutex<A>>`のような形で持たせた
* DB用のメソッドとしてSELECTを実行する`select()`を実装している
  * `rusqlite`でSELECT文を実行
  * `collect`せずiteratorで処理をしたかったので`select()`の引数でクロージャを受け取るようにした
  * クロージャは今後のことも考えて非同期にしている
* `impl A`にメソッドを追加
  * 呼び出し元は`a.lock().await`のようにしてから実行する
  * メソッドの中で`self`のDBインスタンスを使って`select()`を呼ぶ
  * クロージャの中で`self`の`bdk_wallet`インスタンスを使って`mut`がいるメソッドを呼ぶ

最初は`select()`のクロージャも値を`println!`で出力する程度のことしかやっていなかったので困っていなかったのだがこの実装はエラーになった。
`bdk_wallet`は`mut`にしないといけないけど、なんか`mut`にするとエラーになるし。  
`self.db.select()`によって`self`がimmutableになるから`mut`が使えないとかなんとか。  

無理やりにコードを書いてみた。

```toml
[package]
name = "dummy"
version = "0.1.0"
edition = "2024"

[dependencies]
anyhow = "1.0.104"
bdk_wallet = {version = "3.1.0", features = ["rusqlite"]}
serde = {version = "1.0.229", features = ["derive"]}
serde_rusqlite = "0.35.0"
tokio = { version = "1.0", features = ["full"] }
```

```rust
use std::{future::Future, sync::Arc};

use anyhow::Result;
use bdk_wallet::{self, rusqlite};
use serde::Deserialize;
use serde_rusqlite::from_rows;
use tokio::sync::Mutex;

#[derive(Debug, Deserialize)]
struct SomeData {
    pub id: u32,
    pub _name: String,
}

struct Db {
    pub conn: rusqlite::Connection,
}

impl Db {
    pub fn new() -> Self {
        Self {
            conn: rusqlite::Connection::open_in_memory().unwrap(),
        }
    }
    pub async fn select<F, Fut>(&self, mut f: F) -> Result<()>
    where
        F: FnMut(SomeData) -> Fut,
        Fut: Future<Output = ()>,
    {
        let mut stmt = self.conn.prepare("SELECT * FROM my_table")?;
        let iter = from_rows::<SomeData>(stmt.query([])?);
        for result in iter {
            match result {
                Ok(v) => f(v).await,
                Err(e) => {
                    eprintln!("fail convert: {e}");
                }
            };
        }
        Ok(())
    }
}

struct A {
    db: Db,
    btcw: bdk_wallet::PersistedWallet<rusqlite::Connection>,
}

impl A {
    pub async fn go_select(&mut self) {
        let btcw = &mut self.btcw;
        let _ = self.db
            .select(|data: SomeData| async move {
                if data.id == 0 {
                    btcw.reveal_next_address(bdk_wallet::KeychainKind::External);
                    // println!("{}", btcw.balance());
                }
            })
            .await;
    }
}

#[tokio::main]
async fn main() -> Result<()> {
    let mut db = Db::new();
    let Some(wallet) = bdk_wallet::Wallet::load()
        .descriptor(bdk_wallet::KeychainKind::External, Some("hogehoge"))
        .descriptor(bdk_wallet::KeychainKind::Internal, Some("fugafuga"))
        .extract_keys()
        .check_network(bdk_wallet::bitcoin::Network::Testnet)
        .load_wallet(&mut db.conn)
        .unwrap()
    else {
        anyhow::bail!("bad")
    };
    let a = A { db, btcw: wallet };
    let a = Arc::new(Mutex::new(a));
    a.lock().await.go_select().await;
    Ok(())
}
```

`btcw.reveal_next_address`のところでエラーになる。
`reveal_next_address()`は内部の状態を更新するので`mut`がいるのだ。

> cannot move out of `btcw`, a captured variable in an `FnMut` closure
> `btcw` is moved here

## 修正

[Claudeさん](https://claude.ai/share/e0d49269-96c4-41dc-b949-e81951f51a78)曰く。

> いわゆる「非同期クロージャがミュータブルな状態を複数回にわたって借用できない」という、Rustではかなり典型的にハマるポイントです。

とのこと。
「典型的」という言葉を使うことで安心させる効果があると思われる。

2024エディションから`AsyncFnMut`が使えるからこういう修正になる、ということだった。
「async closure」というらしい。  
そうでない場合も対応はできるが、`&self`を`self: Arc<Mutex<A>>`みたいにしてlockしてcloneして.....という手順がいるそうだ。

```rust
use std::sync::Arc;

use anyhow::Result;
use bdk_wallet::{self, rusqlite};
use serde::Deserialize;
use serde_rusqlite::from_rows;
use tokio::sync::Mutex;

#[derive(Debug, Deserialize)]
struct SomeData {
    pub id: u32,
    pub _name: String,
}

struct Db {
    pub conn: rusqlite::Connection,
}

impl Db {
    pub fn new() -> Self {
        Self {
            conn: rusqlite::Connection::open_in_memory().unwrap(),
        }
    }
    pub async fn select<F>(&self, mut f: F) -> Result<()>
    where
        F: AsyncFnMut(SomeData), // ★★AsyncFnMutにしてFutを消す
    {
        let mut stmt = self.conn.prepare("SELECT * FROM my_table")?;
        let iter = from_rows::<SomeData>(stmt.query([])?);
        for result in iter {
            match result {
                Ok(v) => f(v).await,
                Err(e) => {
                    eprintln!("fail convert: {e}");
                }
            };
        }
        Ok(())
    }
}

struct A {
    db: Db,
    btcw: bdk_wallet::PersistedWallet<rusqlite::Connection>,
}

impl A {
    pub async fn go_select(&mut self) { // ★mut
        let btcw = &mut self.btcw; // ★
        let _ = self.db
            .select(async move |data: SomeData| { // ★★async moveが前に移動
                if data.id == 0 {
                    let _ = btcw.reveal_next_address(bdk_wallet::KeychainKind::External);
                }
            })
            .await;
    }
}

#[tokio::main]
async fn main() -> Result<()> {
    let mut db = Db::new();
    let Some(wallet) = bdk_wallet::Wallet::load()
        .descriptor(bdk_wallet::KeychainKind::External, Some("hogehoge"))
        .descriptor(bdk_wallet::KeychainKind::Internal, Some("fugafuga"))
        .extract_keys()
        .check_network(bdk_wallet::bitcoin::Network::Testnet)
        .load_wallet(&mut db.conn)
        .unwrap()
    else {
        anyhow::bail!("bad")
    };
    let a = A { db, btcw: wallet };
    let a = Arc::new(Mutex::new(a));
    a.lock().await.go_select().await;
    Ok(())
}
```

修正箇所はそれほど多くない。  
`FnMut`が`AsyncFnMut`になり、`|data| async move {}`が`async move |data| {}`になったのが大きいところか。

### 何がダメだったか

#### self.dbの借用とクロージャへのmove

`go_select()`の中で`self.db.select()`としているが、この時点で`self.db`が借用になる。
これは`select(&self)`と`&self`になっているからだ。  
その状態でクロージャの中で`self`を使っていて`move`するようにしていると、`self.db`の外側の`self`ごと`move`しようとするので怒られる、ということだろう。

* [参照をキャプチャするか、所有権を移動するか](https://doc.rust-jp.rs/book-ja/ch13-01-closures.html#%E5%8F%82%E7%85%A7%E3%82%92%E3%82%AD%E3%83%A3%E3%83%97%E3%83%81%E3%83%A3%E3%81%99%E3%82%8B%E3%81%8B%E6%89%80%E6%9C%89%E6%A8%A9%E3%82%92%E7%A7%BB%E5%8B%95%E3%81%99%E3%82%8B%E3%81%8B)

じゃあ`async move`としているのを`async`だけにすればよいのでは？と思ったが、非同期のときにブロック内部で環境の変数を使うなら安全のため`move`せよ、ということらしい。
なのでクロージャで非同期なら`async move`はほぼセットになるのだろう。

> async block may outlive the current function, but it borrows `data.id`, which is owned by the current function
> may outlive borrowed value `data.id`

もしクロージャが`FnMut`ではなく`Fn`で`mut`がいらないようであれば今回のような面倒は起きなかったということだ。

#### ループの中でFnMutを呼んでいる

問題はもう1つあって、クロージャを定義しているところで`FnMut`を使っているが、そもそも`mut`な参照をループ内で毎回やり直すということができない、という指摘を受けた。
ループでない場合は問題にならないだけ、ということらしい。
